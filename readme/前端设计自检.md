# 前端设计与工程结构

## 1. 技术栈

- Vue 3 + TypeScript + Vite
- Pinia 业务状态
- shadcn-vue / Reka UI 基础交互组件
- Tailwind CSS 4
- Three.js 参数化模型视口
- Noto Sans SC Variable（思源黑体同源字形）

## 2. 页面结构

- 顶部：Windows 风格应用菜单、任务状态灯和几何内核状态。
- 文档状态栏：图号、任务、单位、当前状态及问题/预算指标。
- 左侧：IDE 式资源管理器，支持文件夹、图纸标签和组合检查入口。
- 文件操作：资源管理器底部打开图纸、创建文件夹、保存工程和读取工程，不再使用拖放区。
- 正文：`01 图纸与任务 → 02 参数化模型 → 03 参数检查 → 04 人工确认` 纵向流程。
- 底部：页面级固定 Dock，切换审查清单、修复记录、回归对比、执行状态和组合检查。

## 3. 项目级能力

- 每个图纸任务拥有独立的建模、审查、修复与导出状态。
- 支持多文档标签切换与关闭。
- 支持创建文件夹并把当前图纸移动到文件夹。
- 支持把资源树中的图纸直接拖到文件夹或“未分类图纸”节点。
- 工程保存为 ZIP；`project.json` 保存工程元数据，原始图纸保存在 `drawings/`。
- 资源管理器高度实时跟随底部 Dock 高度，Dock 展开后不会与工程树重叠。
- 工程进度通过 Pinia 持久化：文档、文件夹、活动标签、任务、模型、审查、修复和 Dock 状态可在刷新后恢复。
- 浏览器本地持久化不包含原始 File/Blob；需要归档图纸本体时使用 ZIP 工程保存。
- 组合检查当前覆盖板厚、孔径、孔数模式等确定性基础接口；干涉与装配约束后续接入后端几何内核。

## 4. 代码边界

```text
src/
  lib/api.ts                  类型化 API 客户端
  stores/workbench.ts         工作台业务状态与动作
  stores/toast.ts             通知状态
  composables/                锚点观察与快捷键
  components/ui/              shadcn-vue 基础组件
  components/workbench/       菜单、状态栏、资源树、标签、阶段、Dock
  components/panels/          业务审查与验证面板
  components/model/           Three.js 视口
  types/api.ts                后端契约类型
```

## 5. 验证命令

```bash
cd frontend
npm run type-check
npm run build

cd ../backend
RUN_HTTP_TESTS=1 python -m pytest tests/test_web.py -q
```

验证范围包括 TypeScript 类型、Vite 生产构建、菜单、固定 Dock、多图纸、文件夹、
ZIP 保存/读取、Three.js 画布交互、字体加载以及 1440/1280/1024/768/390/360 响应式布局。
